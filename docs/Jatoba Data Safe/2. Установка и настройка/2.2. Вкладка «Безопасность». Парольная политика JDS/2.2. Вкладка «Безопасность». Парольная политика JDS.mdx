---
title: 2.2. Вкладка «Безопасность». Парольная политика JDS
---

Парольная политика компонента JDS основана на требованиях, установленных
Приказом ФСТЭК России от 11.02.2013 N 17, к мерам безопасности:

  - ИАФ.4 «Идентификация и аутентификация пользователей, являющихся
    работниками оператора» и усилениям к мере ИАФ.4 (1г, 2);

  - (УПД.6) «Ограничение неуспешных попыток входа в информационную
    систему (доступа к информационной системе)»;

  - Усиление УПД.1(3б) «автоматическое блокирование неактивных
    (неиспользуемых) учетных записей пользователей после
    периода времени неиспользования более 45 дней».

Настройка парольной политики компонента доступна администратору
компонента во вкладке «Безопасность» раздела «Настройки».

### Запрет на использование пароля из списка популярных

Парольные политики компонента JDS имеют параметр «Запрет на
использование пароля из списка популярных».

Проверка используемых паролей выполняется по встроенному файлу
common-passwords.txt, содержащему список запрещенных паролей. Список
возможно изменить или дополнить. Скачав имеющийся файл и внести в
него изменения или загрузив свой файл.

При загрузке файла:

  - Осуществляется проверка на расширение имени файла. Если расширение
    не '.txt', загрузка блокируется;

  - Распознается кодировка файла (UTF-8, UTF-16-LE, UTF-16-BE). Для
    файлов без BOM предполагается кодировка UTF-8.

Для файлов без BOM (Byte Order Mark) осуществляется проверка на
«двоичность»: количество байт "перевод строки" не должно быть
менее 1/100 от общего количества байт. Данная проверка исходит из
предполагаемого содержимого файла (список «популярных» паролей), в
котором скорее всего средняя длина пароля не будет больше 100 символов.
Если обнаружен двоичный файл, загрузка блокируется.

При отображении страницы политики безопасности JDS:

  - Если ранее был сохранен файл с расширением не '.txt', его расширение
    меняется на '.txt'.

  - При скачивании файла, если ранее был сохранен файл с расширением не
    '.txt', его расширение меняется на '.txt'.

### Смена пароля пользователя JDS администратором

Согласно установленной ролевой модели, встроенной учетной записи «admin»
и пользователям с ролью «Администратор СУБД» доступна функциональная
возможность смены пароля всем категориям пользователей JDS без ввода
текущего пароля.

Смена пароля выполняется через контекстное меню в строке пользователя.

<img src={require('/docs/assets/images/jds-gfm/image18.png').default} alt="Описание" />
Рисунок 2.12 – Контекстное меню в строке пользователя JDS

При выборе опции «Сменить пароль» откроется окно «Смена пароля».
Установите или сгенерируйте новый пароль и подтвердите его.

При вводе пароля будет отображаться подсказка по установленным
требованиям к парольной политике, которые устанавливаются во
вкладке «Безопасность».

Вводимая аутентификационная информация будет скрыта, что соответствует
мере защиты информации (ИАФ.5) «Защита обратной связи при вводе
аутентификационной информации», установленной Приказом ФСТЭК
России от 11.02.2013 N 17.

Смена пароля пользователя через служебную БД компонента JDS невозможна.

### Смена пароля пользователем JDS

Поле первичной идентификации, при первом входе в компонент, пользователь
JDS обязан сменить присвоенный ему пароль. При этом, в целях
безопасности, ему не будет доступна и известна
аутентификационная информация для доступа к целевой СУБД.

<img src={require('/docs/assets/images/jds-gfm/image19.png').default} alt="Описание" />
Рисунок 2.13 – Смена пользователем JDS выданного пароля при первом входе

Смена собственного пароля для всех пользователей компонента JDS доступна
через пиктограмму текущего пользователя, расположенную в левом углу
окна.

<img src={require('/docs/assets/images/jds-gfm/image20.png').default} alt="Описание" />
Рисунок 2.14 – Пиктограмма текущего пользователя

При истечении срока действия пароля пользователь будет периодически
получать сообщение о смене пароля.

<img src={require('/docs/assets/images/jds-gfm/image21.png').default} alt="Описание" />
Рисунок 2.15 – Сообщение о смене пароля

Сменить собственный пароль в JDS доступно и через раздел «Настройки» -
вкладка «Пользователи».

В контекстном меню в строке пользователя выбрав опцию «Сменить пароль».

В окне «Смена пароля» вводится и подтверждается новый пароль.
Аутентификационная информация пользователя будет
автоматически изменена.

<img src={require('/docs/assets/images/jds-gfm/image22.png').default} alt="Описание" />
Рисунок 2.16 – Окно смены пароля пользователя JDS

При этом не потребуется повторный вход в компонент JDS.

### Блокирование пользователя JDS администратором

Пользователь JDS, как с парольной, так и с LDAP аутентификацией, может
быть заблокирован администратором принудительно. Такая блокировка
выполняется в карточке пользователя через операцию «Редактировать»
во вкладке «Пользователи» раздела «Настройки».

<img src={require('/docs/assets/images/jds-gfm/image23.png').default} alt="Описание" />
Рисунок 2.17 – Принудительное блокирование пользователя JDS

Ввод комментария является обязательным. Далее она будет отражаться в
карточке пользователя.

### Разблокирование пользователя JDS 

Пользователь JDS может быть заблокирован:

  - компонентом в следствии нарушения парольных политик;

  - администратором компонента;

  - администратором домена.

Статус пользователя отображается в одноименном столбце во вкладке
«Пользователи» раздела «Настройки».

<img src={require('/docs/assets/images/jds-gfm/image24.png').default} alt="Описание" />
Рисунок 2.18 – Разблокировка пользователя JDS

Разблокирование пользователя JDS выполняется администратором компонента
через контекстное меню.

Разблокировка LDAP - пользователя JDS недоступна, если он был
заблокирован администратором домена.
